# Known limits and honest caveats

## Evidence quality
* **Dataset is simulated.** tau2-bench conversations are LLM-simulated customer/agent dialogues; tickets/outcomes are scripted. High scores on them (issue macro-F1 ≈ 0.997) say the pipeline works on *that* distribution, not that it works on real calls. Real transcripts will contain far more noise, mixed intents, and ASR error.
* **Synthetic suites are optimistic.** Compliance, issue and redaction scores on `data/synth.py` conversations are derived from the same templates that produced them. Treat them as regression tests, not accuracy claims. Only the "tau2 test split" numbers use data the models never trained on, and `models_eval/` is trained on the train split only to keep that true.
* **Retrieval relevance is weak supervision** (a chunk is relevant if it mentions a step the gold solution performs).
* **Business value is an expected value under stated assumptions** (`value/model.py: ASSUMPTIONS`), not a measured uplift. It requires an A/B test.
* **Unmeasured compliance rules.** R4/R5/R7/R8/R9/R10 have no ground-truth labels in any dataset here; they are covered by mutation tests (a violation is injected and must be detected) only.

## Weak spots measured (and published in the eval report)
| Area | Result | Implication |
|---|---|---|
| Sentiment trend | 0.69 accuracy | Do not auto-act on sentiment alone |
| Sarcasm | recall 0.56 | Will miss some irritated customers |
| tau2 fix-selection | F1 0.43 | Root cause is reliable at family level, less so on the exact fix |
| Churn under 30% ASR noise | recall 0.61 | Expect degradation on poor audio |
| Injection leave-one-family-out | min recall 0.64 (“coerce” family) | Unseen attack styles are caught less often; the policy engine is the real defence |

## Further findings from the final gated run (79/79 gates pass; gates were tuned to measured behaviour, so passing them is a regression guard, not proof of quality)
* **Hybrid retrieval ≈ lexical.** On 28 weakly-labelled queries hybrid MRR is 0.468 vs lexical 0.447 (+0.02) and hybrid R@5 (0.82) is *below* lexical R@5 (0.93). Hybrid is kept for robustness to paraphrase, but the data does not show a clear win; the sample is small.
* **Root-cause exact-set match is low** (0.14 on tau2 test) although micro-F1 is 0.80 and “any gold cause hit” is 0.99: tickets often carry several causes; the system finds the right family but rarely the exact set.
* **Drift on clean data is not silent:** no *alerts*, but two *warns* (conversation-length PSI 0.17, injection-rate) → recommendation `INVESTIGATE`. Mix-shift and ASR-shift are both detected as alerts.
* **ASR-noise results on synthetic data are optimistic:** issue F1 stays 1.0 even at WER 0.31 because the templates are keyword-rich. Only churn recall (0.61 at WER 0.31) shows real degradation. Do not quote the issue-F1 number as noise robustness.
* **Agent mesh action scores (0.97 micro-F1)** are on synthetic scenarios whose gold actions come from the generator.
* **Retention precision is 0.88:** about 1 in 8 proposed retention offers goes to a customer the generator did not label as at-risk; offers are approval-gated above the limits.

## Engineering gaps (not exercised here)
* **Never executed in the build sandbox:** Terraform (`plan`/`apply`), Docker builds, Cloud Build, `scripts/release.sh`, `scripts/canary_check.py`, `runtime/serve.py` + `scripts/demo.py` (all-in-one dev server), docker-compose stack. They were written carefully and cross-checked by tests that parse the generated files, but run `terraform validate`/`plan` and a dev deploy before trusting them.
* **GCP clients untested live:** Pub/Sub, BigQuery, Firestore, Vertex/Anthropic LLM adapter and the Salesforce/ServiceNow/billing connectors run only against emulators/simulators or mocks.
* **`FirestoreVault` uses the sync client in async handlers** (ADR-002).
* **Secrets in Terraform state:** random keys are generated by Terraform and stored in state and Secret Manager. Use a locked-down, CMEK-encrypted state bucket, or create the secrets out-of-band and import them.
* **Monitor is single-instance** (ADR-005).
* **Tenant isolation is logical**, not per-project.
* **Names in free text** are found by cues/known names, not NER; unusual names introduced without a cue (“it's Zbigniew calling”) can slip through the first pass (the second pass and the attestation still gate what leaves redaction, but recall on names is lower than on structured PII).
* **No audio path** (ASR, diarisation, voiceprint, crosstalk) – out of scope; see SCOPE.md.
* **Retraining is manual** (`make train`); no automated promotion or shadow deployment.
* **Legacy v1 files** (`src/`, old `tests/`) remain in the repository because the delivery tooling cannot delete files on your machine; see README for the exact delete commands.
* **Vendored dependencies are not shipped**; install from `requirements.txt` (the sandbox had PyPI blocked, so versions were verified only against what was vendored there).
